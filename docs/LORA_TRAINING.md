# 古诗 LoRA 微调 · 数据清洗管线与训练记录

本文档存档 InkVerse 本地诗歌模型（Qwen2.5-1.5B + LoRA）的上游过程：数据从哪来、怎么洗、怎么训、效果如何。清洗管线脚本（`poetry_sft_pipeline/`，config + utils + step1~5）在独立的数据工程目录维护，不随本仓库分发；本文是其流程与结果的入库记录。

- 原始语料：[CanvaChen/llm-dataset-chinese-poetry](https://github.com/CanvaChen/llm-dataset-chinese-poetry)（12 个文件，346,024 首）
- 最终权重：[Judy-Liu118/poetry-lora](https://huggingface.co/Judy-Liu118/poetry-lora)（对应 checkpoint-3375，eval loss 最优步）

## 1. 数据管线总览

五阶段清洗，从 34.6 万首原始古诗到 3 万条 SFT 对话样本：

```
原始诗歌 (346,024 首)
  → Step1 格律筛选 + 元数据提取   → 181,089 首（五绝 9,863 / 七绝 72,763 / 五律 43,238 / 七律 55,225）
  → Step2 均衡采样               → 30,000 首（四体裁各 25%）
  → Step3 指令生成               → 每首配一条"创作类"用户指令
  → Step4 格式转换               → conversations 对话格式（user 指令 / assistant 诗文）
  → Step5 训练文本               → Qwen2.5 chat 模板纯文本（统一 system prompt）
```

每一步只做一件事：Step1→2 是元数据的筛选与重组，Step2→3 是"贴指令"，Step3→4 是"瘦身为标准对话格式"，Step4→5 是"套壳为具体模型的训练文本"。

## 2. 各阶段要点

**Step1 · 格律筛选与元数据提取**（`pingshui_rhyme` 平水韵库，多进程并行）

- 按标点切分诗句，统一句长/句数后分类为五绝/七绝/五律/七律；非 4/8 句或长短不一律弃
- 平仄校验只看关键位置（五言第 2、4 字，七言第 2、4、6 字），比对仄起/平起 × 入韵/不入韵四种标准谱式——即传统"一三五不论、二四六分明"，而非逐字硬匹配
- **名诗白名单**：TOP_POETS（李白、杜甫等 24 位大家）作品即使平仄判定不合规也保留（古今音变/通假可能造成误判），但如实标记 `is_rhythmic`；非名家作品必须平仄合格才保留
- 同时产出：标题清洗、主题关键词（内置主题词表优先，查不到用 jieba 分词兜底）、韵脚

**Step2 · 均衡采样**（30,000 首，四体裁各 7,500）

- 三类样本混合，**名诗出律样本配额 ≤5%**——既保住经典名篇，又防止模型把"出律的名家范例"当成正确平仄学走
- 实际构成：普通诗 86.6% / 名诗合律 8.4% / 名诗出律 5.0%

**Step3 · 指令生成**

- 主力为规则模板：主题/续写/标题/作者风格/押韵/自由创作等多类加权随机组合；**主题类权重始终最高、续写与标题类刻意压低**（让训练分布偏向开放式创作而非背诵原句）；顶级诗人提高"模仿风格"权重
- 40% 概率插入"格律严谨的"等修饰语——**仅当该诗真实平仄合格时**（指令语义与标签一致性）
- 可选 LLM 生成通道（本地 Qwen2.5-7B-4bit，比例 20%），带长度/诗体关键词/措辞的后处理过滤，失败回退模板；支持 md5 断点续传

**Step4/5 · 格式转换**

- Step4：`{instruction, content}` → conversations 双轮格式，丢弃 meta（溯源信息保留在 Step3 产物中）
- Step5：拼装 Qwen2.5 chat 模板，统一 system prompt（"你是一位精通中国古典诗词的创作专家……"），直接供 Unsloth SFTTrainer 使用

## 3. 一条数据的全程流转（示例）

以李纲《以蜜渍荔枝寄远》（七律，韵"支"）为例：

| 阶段 | 数据形态 |
|---|---|
| Step1/2 | `{content, author, title, poem_type: "七律", topic: "荔枝", rhyme: "支", is_rhythmic: true, keywords, ...}` 纯元数据 |
| Step3 | 上述 meta + `instruction: "创作一首关于'荔枝'的格律严谨的七言律诗。"`（命中主题类模板 + 合律修饰语） |
| Step4 | `{conversations: [{role: user, content: 指令}, {role: assistant, content: 诗文}]}` |
| Step5 | `{text: "<\|im_start\|>system\n你是一位精通中国古典诗词的创作专家……<\|im_end\|>\n<\|im_start\|>user\n……"}` |

## 4. 训练配置与收敛

| 项 | 值 |
|---|---|
| 基座 | Qwen2.5-1.5B-Instruct（Unsloth 4bit 量化加载） |
| LoRA | rank=8 · alpha=16 |
| 数据 | 30,000 条，seed=42 随机打乱后 9:1 切分训练/验证 |
| 训练量 | 全量 1 epoch，共 3,375 步，`load_best_model_at_end=True` |

Loss 轨迹（trainer_state）：

| step | epoch | train loss | eval loss |
|---|---|---|---|
| 50 | 0.01 | 2.17 | — |
| 750 | 0.22 | 1.57 | 1.5555 |
| 1500 | 0.44 | 1.56 | 1.5428 |
| 2250 | 0.67 | 1.53 | 1.5345 |
| 3000 | 0.89 | 1.55 | 1.5272 |
| 3375（最终） | 1.00 | 1.58 | **1.5259（最优）** |

前 100 步 train loss 从 2.17 快速降至 ~1.6 后进入平台期；eval loss 全程单调下降、无回升——收敛稳定、未见过拟合，最优步恰为最后一步，保存权重即最优模型。

## 5. 微调前后对比（同 8 个提示词）

最直观的一组——「五言绝句·春天」：

| | 生成结果 |
|---|---|
| 微调前 | 春风拂柳绿，细雨润花红。燕舞莺歌里，人间四月芳菲尽（末句 7 字，破格） |
| 微调后 | 春风吹柳绿，江水向东流。桃花笑含露，燕子舞轻柔。（四句均 5 字，格律工整） |

其余 7 个主题（荷花七律、孤舟五律、山居五律、边塞七绝、夜雨五绝、咏竹七绝、登高五律）微调前后均能大致遵守字数格式，但微调后的用词与意象组合更贴近古典措辞习惯（"绰约风姿""烽烟未歇""凌风傲骨"等），整体更有诗味。

## 6. 与本仓库评估结论的相互印证

数据侧的两个设计决策，与下游 n=32 × 3 run 主跑评估（[REPORT_main_n32x3run](../eval/REPORT_main_n32x3run_20260624.md)）的发现构成一致性解释（相互印证，非因果证明）：

1. **只收平仄合格样本 + 出律配额 ≤5%** ↔ 评估发现 LoRA 把格律内化进权重：移除格式 prompt（naked 模式）后平仄合格率不降反升至 96.4%——格律来自训练数据分布本身，不依赖 in-context 引导
2. **训练数据全部过硬门控筛选** ↔ 评估发现 LoRA 提升地板不提升天花板（pass@0.7 合格率 36.2%→64.0%，best 候选持平）——SFT 收紧输出分布、砍掉坏样本，符合 alignment fine-tune 的典型 pattern
